分層架構速查表

對應 Lesson 0001，以 dudupay-spa 的註冊流程為例。

四層 & 各自唯一的職責

  • typesrc/types/registration.ts — 定義資料「長什麼樣子」。零依賴，純詞彙表。
  • ↓ 只能被下面的層 import，自己誰都不 import
  • configsrc/config/registrationSteps.ts — 定義步驟「順序、路徑、標題」。依賴 type。唯一事實來源（single source of truth）。
  • ↓ 依賴 type + config
  • storesrc/stores/registration.ts — 管理「當下的即時狀態」+ 持久化。依賴 type + config。
  • ↓ 依賴 type + config + store
  • routersrc/router/index.ts — 根據 store 的狀態 + config 的順序，決定「現在准不准進某個路徑」。

唯一規則

依賴只能往下看，不能往上看。上層可以認識下層，下層永遠不知道上層存在。

來源：Feature-Sliced Design — Layers 的 Import Rule。

加新步驟時，照這個順序改

  1. types/registration.ts — 先定義新步驟的資料形狀 + 加進 StepKey
  2. config/registrationSteps.ts — 補上這個步驟的 order / path / title
  3. stores/registration.ts — 補上這個步驟的預設值 + 持久化欄位
  4. router/index.ts — 補上這個步驟對應的 component

聞到壞味道的訊號

  • 循環 import：下層的檔案（例如 type）import 了上層的檔案（例如 router）。
  • 順序被寫兩份：store 或 router 裡自己又寫了一份步驟順序，沒有從 config 讀。代表 single source of truth 被打破了，兩份清單遲早會不同步。
  • 硬編碼字串：路徑字串（如 '/register/upload'）在 config 以外的地方又出現一次。
