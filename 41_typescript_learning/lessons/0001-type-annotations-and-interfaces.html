型別標註與 interface：讀懂資料的形狀

目標：看懂 dudupay-spa 專案裡最基本的型別寫法，為讀懂 router/index.ts 打地基。

TypeScript 到底是什麼

TypeScript 是 JavaScript 加上「型別標註」。你寫的每一個 : string、: boolean 都只在你寫程式、編譯的當下有用——瀏覽器實際執行時，這些標註會被整個拿掉，剩下純 JavaScript。 它的用途是讓編輯器和編譯器提早告訴你：「這裡塞錯型別的值了」，而不是等到執行期才炸掉。

主要參考：TypeScript Handbook: TypeScript for JavaScript Programmers

基本型別標註

來看專案裡真實的程式碼。這是 src/types/registration.ts 裡的一段： 

export interface Step1Account {
  password: string
  confirmPassword: string
  email: string
  mobile: string
  agreedTerms: boolean
}

規則很單純：欄位名稱: 型別。password 這個欄位的值必須是 string（字串）， agreedTerms 必須是 boolean（true 或 false）。 如果哪裡塞了一個數字給 password，編輯器會立刻標紅色底線警告你。

聯集型別：這欄位可能是好幾種型別之一

同一份檔案裡，Step2Upload 長這樣： 

export interface Step2Upload {
  idFront: string | null
  idBack: string | null
  selfie: string | null
}

string | null 中間這個直線 | 唸作「或」，叫做聯集型別（union type）。 意思是：idFront 這個欄位的值，可能是一個字串（例如上傳後的圖片網址），也可能是 null （代表「使用者還沒上傳」）。這是 TypeScript 用來表達「這個值現在可能還沒有」的標準寫法，比起隨便塞一個空字串 "" 更精確——因為「空字串」和「還沒有值」的語意其實不一樣。

Q1. idFront: string | null 這一行裡，string | null 是什麼型別？

interface 在做什麼

Step1Account、Step2Upload 前面都有一個 export interface。 interface 是在幫一整包「物件應該長什麼樣子」取一個名字——這個物件有哪些欄位、每個欄位是什麼型別。 取完名字之後，別的地方就能直接寫 : Step1Account 來標註「這個東西的形狀要符合 Step1Account」， 不用每次都把六、七個欄位重寫一遍。export 則是讓其他檔案可以 import 這個名字來用—— 這部分你在 Vue Router 裡應該已經很熟悉了，是同一套模組系統。

Q2. Step1Account 前面的 interface 關鍵字，是在做什麼？

往前看一眼：這在 router/index.ts 裡會怎麼用

你的目標檔案 src/router/index.ts 第 4 行有這一句： 

import type { StepKey } from '../types/registration'

StepKey 就是 types/registration.ts 裡另一個型別——它跟今天學的 interface 是親戚，但用的是 type 加上字串聯集（下一課會講）。import type 這個寫法本身也是新語法： 它明確告訴 TypeScript「我只是要借用這個型別的定義來檢查程式碼，不需要真的把它打包進最後執行的 JS」。 這兩個語法，加上 router/index.ts 第 13 行的 Record<StepKey, ...>， 就是下一課要拆解的東西。今天先把「型別標註」和「interface 是什麼」這兩件事練熟，是後面所有語法的地基。

今天的收穫
看到 欄位: 型別、A | B、interface Xxx { ... } 這三種寫法， 你現在應該能唸出它們在講什麼了。可以翻開 src/types/registration.ts 整份檔案， 試著逐行讀讀看——裡面幾乎全是今天學的這幾種語法的重複組合。
卡住的地方隨時問我——尤其是「為什麼要這樣寫」而不只是「這是什麼」。這是持續好幾次課程的學習， 你可以隨時回來繼續，我會記得你學到哪裡。
