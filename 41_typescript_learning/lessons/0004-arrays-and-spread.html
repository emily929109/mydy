陣列型別：Type[]

23
const routes: RouteRecordRaw[] = [

型別名稱後面加一對方括號 []，代表「一個陣列，每一個元素都要符合這個型別」。 RouteRecordRaw[] 就是「一個陣列，裡面每一個元素都要是 RouteRecordRaw 形狀的物件」。 這跟 string[]（字串陣列）、number[]（數字陣列）是同一種寫法，只是這裡的元素型別 是 Lesson 3 提過的那個 interface。

主要參考：TypeScript Handbook: Everyday Types — Arrays

Q1. step2: RouteRecordRaw[] 代表 step2 是什麼？

展開運算子 ...：這不是 TypeScript，是 JavaScript

23
const routes: RouteRecordRaw[] = [
24
{ path: '/', redirect: registrationSteps[0].path },
25
...registrationSteps.map((step) => ({
26
path: step.path,
27
name: step.key,
28
component: stepComponents[step.key],
29
})),
30
]

先講清楚一件事：這一段裡真正跟型別有關的只有第 23 行的 RouteRecordRaw[]。 第 25 行開頭的 ...（展開運算子，spread syntax）跟後面的 .map() 都是純 JavaScript 語法，跟 TypeScript 無關——之所以放進這一課，是因為它們跟型別語法混在同一段程式碼裡， 不順便講清楚很容易誤以為「這也是什麼特殊的型別寫法」。

... 放在陣列字面值 [...] 裡面時，意思是「把後面這個陣列的每一個元素各自攤開放進來， 不是把整個陣列當成一個元素塞進去」。對照著看： 

const a = [1, 2, 3]
[0, a]     // 結果：[0, [1, 2, 3]] —— a 整包被當成一個元素
[0, ...a]  // 結果：[0, 1, 2, 3]  —— a 的每個元素被攤開

所以第 25 行 ...registrationSteps.map(...) 的意思是：先用 .map() 把 registrationSteps（每個步驟的設定陣列）轉換成一個新陣列，每個元素長成 { path, name, component } 的形狀，再用 ... 把這個新陣列的每個元素攤開， 接在第 24 行那個手寫的路由物件後面，一起變成 routes 陣列的元素——不是巢狀塞進去變成 routes 裡的第二個元素是「另一個陣列」。

另外第 25 行結尾和第 29 行的括號 ({ ... }) 也有個容易忽略的細節：箭頭函式如果要直接回傳一個物件字面值， 外面一定要包一層小括號 ( )。原因是 => { 這個 { 預設會被讀成「函式本體的開始」，而不是「物件字面值的開始」；包一層括號後，JavaScript 才知道裡面是要回傳的物件。

主要參考：MDN: Spread syntax (...)

Q2. const b = [9, ...[1, 2]] 執行後，b 會是什麼？

順便一提：這裡沒寫型別，TypeScript 怎麼知道對不對

你可能注意到 .map((step) => ({ ... })) 這段完全沒寫任何 : 型別—— 沒人告訴 TypeScript step 是什麼型別，也沒人說回傳的物件要符合什麼形狀。這是因為 TypeScript 會做型別推斷（inference）：它從 registrationSteps 這個陣列本身的型別， 推出 .map() 裡的 step 是什麼形狀；又因為整個 routes 被標成 RouteRecordRaw[]，它會反過來檢查 .map() 吐出來的每個物件符不符合 RouteRecordRaw。不是所有地方都要手寫型別，很多時候 TypeScript 能自己從上下文推出來。
