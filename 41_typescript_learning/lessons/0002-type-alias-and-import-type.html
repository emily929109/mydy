type 別名與 import type：宣告與匯入型別的語法

目標：看懂 src/router/index.ts 第 1 行和第 4 行的 import，以及 StepKey 這個型別怎麼定義出來的。

上次學到哪
Lesson 1 學了 interface：幫一整包物件的形狀取名字。今天要學的 type 是它的親戚， 但用途更廣——不只物件，任何型別都能取名字。看不熟的話可以先回顧 Lesson 1。

type 別名：不只是物件形狀

src/types/registration.ts 裡有這一段： 

export type StepKey =
  | 'step1Account'
  | 'step2Upload'
  | 'step3Info'
  | 'step4TwcaConsent'
  | 'step5TwcaClause'
  | 'step6TwcaVerify'
  | 'step7Sign'

type StepKey = ... 是在幫等號右邊的型別取一個名字，叫 StepKey。跟 interface 不一樣的地方是：interface 只能拿來命名「物件的形狀」，type 什麼型別都能命名——這裡命名的 是一串字串字面值的聯集：StepKey 這個型別的值，只能是 'step1Account'、'step2Upload' ⋯ 這七個字串當中的其中一個，不能是任何其他字串。

這跟 Lesson 1 學的 string 差很多：string 允許「任何字串」， 而 StepKey 只允許「這七個字串之一」。如果程式裡哪裡塞了一個 'step8Whatever' 給要求 StepKey 的地方，編輯器會直接標紅——這是 TypeScript 用來表達「這欄位只能是固定幾種值之一」 的標準寫法，比起用註解寫「請只填這幾種值」再靠人肉檢查可靠得多。

主要參考：TypeScript Handbook: Everyday Types — Type Aliases

Q1. 如果某個函式參數型別是 StepKey，下面哪個呼叫方式會被 TypeScript 標紅色錯誤？

import type：只借型別，不借程式碼

來看 src/router/index.ts 開頭兩行 import：

1
import { createRouter, createWebHistory, type RouteRecordRaw } from 'vue-router'
4
import type { StepKey } from '../types/registration'

這兩行都在匯入東西，但意義不一樣。第 1 行裡，createRouter 和 createWebHistory 是真正的函式——執行的時候會被呼叫，會被打包進最後的 JS。但同一行裡的 type RouteRecordRaw 前面多了 type 這個字，代表「這個名字只是型別，不是可以執行的東西」。 第 4 行的 import type { StepKey } from ... 是同一件事的另一種寫法：整行 import 進來的東西 全部都只是型別，所以把 type 放在最前面，一次講清楚。

這兩種寫法（行內 type 修飾單一個名字 / 整行開頭 import type）效果相同： 編譯成瀏覽器能跑的 JS 時，這些型別 import 會被整行刪掉，因為型別本來就只在寫程式、編譯的當下有用， 跟 Lesson 1 提過的「型別標註在執行期會被拿掉」是同一個道理——只是這次拿掉的是整條 import 敘述，不是欄位後面的 : string。

主要參考：TypeScript Handbook: Type-Only Imports and Export

Q2. router/index.ts 第 1 行裡，哪一個名字在編譯成 JS 之後不會被拿掉？

往前看一眼：下一課

router/index.ts 第 13 行還有這個： 

const stepComponents: Record<StepKey, RouteRecordRaw['component']> = { ... }

今天學的 StepKey 會在這裡被拿來當「查表用的鍵」。Record<...> 這種尖括號寫法叫 泛型（generic），加上 RouteRecordRaw['component'] 這種從型別裡「挖」出某個欄位型別的寫法， 是下一課要拆的東西。今天先把 type 別名和 import type 練熟——這兩個是讀懂下一課的地基。
