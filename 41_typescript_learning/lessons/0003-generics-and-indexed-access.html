泛型：Record<K, V>

Record 是 TypeScript 內建的型別，用來描述「一個物件，鍵是某個型別，值是另一個型別」。 尖括號 <K, V> 裡填的兩個型別就是「鍵的型別」和「值的型別」——這種可以填入不同型別、 讓同一個型別定義重複使用的寫法叫泛型（generic）。Record<StepKey, RouteRecordRaw['component']> 意思就是：一個物件，鍵必須是 StepKey（七個固定字串之一），值必須是 RouteRecordRaw['component'] 型別。

這裡有個關鍵效果：因為 StepKey 是「剛好七個字串」的聯集（不是隨便字串）， Record<StepKey, ...> 會要求物件剛好有這七個鍵，一個不多一個不少。 如果第 14~20 行漏寫了一個 step3Info，TypeScript 會直接報錯說少了這個屬性—— 這就是 Lesson 2 說「用固定聯集取代隨便字串」的好處在這裡兌現了：每加一個新步驟到 StepKey， 這個物件沒補上對應元件就會編譯失敗，不會不小心漏掉。

主要參考：TypeScript Handbook: Utility Types — Record

Indexed Access Type：RouteRecordRaw['component']

再看值的型別：RouteRecordRaw['component']。RouteRecordRaw 是 vue-router 提供的一個 interface（Lesson 1 學過的那種），描述一條路由設定長什麼樣子，裡面有一個 component 欄位。 RouteRecordRaw['component'] 這種方括號寫法，意思是「去 RouteRecordRaw 這個型別裡， 把 component 這個欄位本身的型別挖出來用」——語法長得很像執行期在物件上用 obj['component'] 取值，但這裡是在型別的世界做同樣的事，取出來的不是值，是型別。

為什麼要繞這一圈，不直接手寫 component 應該是什麼型別？因為 RouteRecordRaw 是 vue-router 套件定義的，它的 component 欄位型別可能很複雜（要能接受好幾種元件寫法）。 與其自己重寫一份容易寫錯、也容易在套件更新後過期的型別，不如直接跟套件本身的定義「借」，保證永遠同步。

主要參考：TypeScript Handbook: Indexed Access Types
