# 聯集當「值」vs 聯集當「Record 的鍵」，是兩種不同效果

使用者對 Lesson 3 提出疑問：`StepKey` 是七選一的聯集，為什麼 `Record<StepKey, RouteRecordRaw['component']>` 卻要求物件「剛好有七個 key」，感覺跟「七選一」矛盾。

這暴露了一個容易誤解的地方：同一個聯集型別，用在不同位置意義完全不同。

- 聯集當一個**值**的型別（例如 `idFront: string | null`，或某個變數是 `StepKey`）：代表「這個位置在某一刻只能是其中一個」。
- 聯集當 `Record<K, V>` 的**鍵型別參數**：`Record<K, V>` 內部是 mapped type `{ [P in K]: V }`，`in` 會把 K 聯集的**每一個成員各自展開成一個欄位**，所以最後要求的是「全部成員都要有對應欄位」，不是「挑一個」。

使用者在問這題之前，才剛在同一個檔案裡問過 `Step2Upload` 的 `string | null`（單一值的聯集），兩者放在一起對照理解效果最好——之後設計課程遇到聯集型別，若同時牽涉「值的位置」和「泛型鍵的位置」，應該主動並排說明，不要預設使用者會自己類推過去。

未來可能需要的後續：mapped type（`{ [P in K]: V }`）本身目前只帶過一句話，還沒正式教。如果使用者之後在專案裡遇到自訂的 mapped type，應該補一課正式講解，目前 [[MISSION]] 的 out of scope 有註明「除非之後真的在專案裡遇到才補」，這正是那個情境。
