System.Web.Optimization 的壓縮essence — 供之後隨時查閱，不是教學文。

雜湊版號怎麼來的

@@Scripts.Render("~/bundles/xxx") 產生的網址帶一個 ?v=... query string，這個 token 是依 bundle 內所有檔案的內容算出來的雜湊值，不是時間戳、不是檔案的 Last-Modified。

  • bundle 內容不變 → token 不變 → 瀏覽器吃快取（不重新下載）
  • bundle 內任一檔案改了 → token 換一個 → 網址整個不同 → 瀏覽器一定重新下載
  • token 在伺服器端 render HTML 當下就算好、內嵌進 HTML 了 — 前端不用發任何額外 request 去判斷要不要吃快取

Bundling 生不生效，兩個開關

設定值結果
web.config
<compilation debug="...">		true不合併、不壓縮、不產生雜湊版號（除非 EnableOptimizations 蓋過它）
同上false合併＋壓縮＋雜湊版號，全部生效
BundleTable.EnableOptimizations（C# 程式碼）true強制生效，蓋過 web.config 的 debug 設定

來源：Bundling and Minification — Microsoft Learn §Controlling Bundling and Minification

地雷

正式環境如果 Publish Profile 沒切到 Release、或 web.config 還留著 debug="true"，這個方案完全不會生效 — 版號問題會原封不動地回來，而且不會有任何錯誤訊息提示你。發佈後務必實際看一次頁面原始碼，確認 <script> 網址上真的帶了 ?v=。

BundleConfig.cs 骨架（共用 + 各頁專屬）

// App_Start/BundleConfig.cs
public class BundleConfig
{
    public static void RegisterBundles(BundleCollection bundles)
    {
        // 所有頁面都會用到的
        bundles.Add(new ScriptBundle("~/bundles/common").Include(
            "~/Scripts/jquery-{version}.js",
            "~/Scripts/site.js"));

        // 只有商品頁用到的
        bundles.Add(new ScriptBundle("~/bundles/productPage").Include(
            "~/Scripts/product-detail.js"));

        // 只有結帳頁用到的
        bundles.Add(new ScriptBundle("~/bundles/checkoutPage").Include(
            "~/Scripts/checkout.js"));

        BundleTable.EnableOptimizations = true; // 正式環境強制生效，不依賴 web.config
    }
}

頁面上用 @@Scripts.Render("~/bundles/common") 引用；各頁 View 再各自加對應的專屬 bundle。

IIS 靜態檔案長效快取（非 bundle 的檔案）

Bundle 的 HTTP 回應框架已經自動帶了一年後過期的 Expires header，不用另外設定。但圖片、字型等「沒有走 bundling」的靜態檔案，預設不一定有長效快取 header，要在 web.config 補：

<system.webServer>
  <staticContent>
    <clientCache cacheControlMode="UseMaxAge" cacheControlMaxAge="365.00:00:00" />
  </staticContent>
</system.webServer>
屬性作用
cacheControlModeNoControl（預設，不加 header）／DisableCache／UseMaxAge／UseExpires
cacheControlMaxAge搭配 UseMaxAge，格式 天.時:分:秒，範例中 365.00:00:00 = 一年
httpExpires搭配 UseExpires，指定絕對日期時間（RFC 1123 格式）

來源：Client Cache <clientCache> — Microsoft Learn (IIS docs)

下週一查證 checklist（對應 handoff 的 Q5 / Q8）

  • ☐ App_Start/BundleConfig.cs 存不存在？有沒有已經在用？
  • ☐ 正式環境 .pubxml 對應的組態確實是 Release，且 web.config 中 debug="false"
  • ☐ 圖片等非 bundle 靜態檔案的 clientCache 有沒有設定
  • ☐ 盤點所有手動 ?v=... 的頁面，準備改成 @@Scripts.Render(...)
  • ☐ 找到並移除現有 fetch HEAD 比對 Last-Modified 的 JS（白屏根源）
