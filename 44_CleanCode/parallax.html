看方塊漂浮

32 個方塊被套用一模一樣的位移，看起來速度不同，是因為 CSS 3D 透視：離你越近的動得越多。

自動展示中 · 移動滑鼠接手

實驗開關

數字越小，透視越強，深淺方塊的速度差越大。
越高越「拖」。原站設定 97，每幀只追上剩下距離的 3%。

各深度的移動倍率

深度 translateZ 數量 畫面上的倍率

倍率 = perspective ÷ (perspective − z)。滑鼠從最左移到最右，深度 0 的方塊移動 192px（±6rem），其他深度依倍率放大或縮小。

三個重點

位移只算一次

JS 只在外層容器設定 --mx、--my 兩個變數，所有方塊共用，不用逐一計算每顆。

速度差交給透視

外層 div 用 translateZ 決定深度，內層 div 跟著滑鼠移動。兩層分開，兩個 transform 才不會互相覆蓋。

亂中有序

其實是 8 欄 × 4 列的整齊 Grid，有的格子透明、有的只有框線，加上透視把位置推歪，看起來就像隨機排列。

核心程式碼

HTML
<!-- 外層管深度，內層管移動 -->
<div class="tiles">
  <div class="z" data-d="2">
    <div class="xy">JS</div>
  </div>
  <div class="z" data-d="-2">
    <div class="xy outline"></div>
  </div>
  <!-- …共 32 格 -->
</div>
CSS
.tiles {
  display: grid;
  grid-template-columns: repeat(8, 1fr);
  place-items: center;
  perspective: 350px;
}
.z { transform-style: preserve-3d; }
.z[data-d="2"]  { transform: translateZ(96px); }
.z[data-d="-2"] { transform: translateZ(-96px); }
.xy {
  transform: translate(
    var(--mx), var(--my));
}
JavaScript
const R = 96; // ±6rem
let tx = 0, ty = 0, x = 0, y = 0;
addEventListener('pointermove', e => {
  tx = (e.clientX / innerWidth  * 2 - 1) * R;
  ty = (e.clientY / innerHeight * 2 - 1) * R;
});
(function tick() {
  x += (tx - x) * 0.03; // smoothing 97
  y += (ty - y) * 0.03;
  tiles.style.setProperty('--mx', x + 'px');
  tiles.style.setProperty('--my', y + 'px');
  requestAnimationFrame(tick);
})();
