密碼規則寫在 register.js 的 Next 函式(第97~272行)裡,是下一步/送出表單時做的前端驗證,不是即時驗證(沒有 watch,只在點擊按鈕呼叫 Next() 時才跑一次)。規則本身用最原始的「陣列 + indexOf 迴圈」寫法,不是用正規表達式。具體規則如下:

1. 長度(155~165行)
if (pw_register.v.length < 8 || pw_register.v.length > 18)
→ 8~18 字。

2. 必須包含大寫英文(169~197行)
用 letters 陣列(A~Z,但故意排除了 I 跟 O——不對,仔細看陣列裡有放 I、O,但排除了容易跟數字混淆的位置沒有特別規律,其實 26 個字母都在,只是順序打散了)逐一 indexOf 檢查。

3. 必須包含小寫英文(199~216行)
同樣邏輯,用 letters2(a~z)。

4. 必須包含數字(217~234行)
用 letters3 = ['1'~'9','0']。

5. 不能包含特定特殊字元(236~253行) ⚠️ 這條容易誤解
var letters4 = ['!', '！', '@', '#', '$', '%', '&'];
if (hasSpecChar) { error = 'ng'; msg = '不能有特殊字如: !@#$%&'; }
邏輯是反過來的——只要密碼含有 ! ！ @ # $ % & 這 7 個字元其中之一,就判定不合法。也就是說這不是「特殊字元黑名單擋掉危險字元」的安全性考量,而是規則本身就禁止這幾個符號出現在密碼裡(其他符號如 _、-、. 等沒有被檢查,是允許的)。

6. 兩次密碼要相同(255~263行)
if (pw_register.v != repw_register.v)

彙整規則:8~18字元、需同時包含大寫+小寫+數字、且不能含 !！@#$%& 這幾個符號、兩次輸入需一致。

順帶一提,這段程式碼有個真實的邏輯瑕疵:每一條規則檢查失敗後都是單獨 return(第160、192、211、229、248行),代表一次只會顯示第一個踩到的錯誤——例如密碼同時「太短」又「沒有大寫」,使用者只會看到「密碼至少8字」的訊息,改完後重新送出才會看到下一條「要有英文大寫」,得試好幾次才能看到完整規則,體驗上比較不友善。如果要一次列出所有不符合的規則,需要把這些 if/return 改成累積錯誤訊息而不是逐一 return。需要我調整嗎?
